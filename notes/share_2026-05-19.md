## 為什麼這兩個分析放一起講

如果只看其中一個，會覺得是某個特定產品的問題。兩個放一起，看到的是**鏈上市場結構的一致性現象**：

| 觀察 | 從交易角度 (Dashboard 1) | 從持有角度 (Dashboard 2) |
|---|---|---|
| 表面看像「大眾在用」 | 25 家以上的 DEX | 690 萬個 USDC 持有地址 |
| 實際集中在少數玩家手上 | **前 3 家 = 82% 成交額** | **前 1 萬個地址 = 89% 供應量** |
| 長尾的長度 vs 重量 | 18 個尾巴 DEX 加總 1.3% | 690 萬個尾巴地址加總 11% |

也就是說，鏈上資料的「散戶 / 大眾」敘事跟「實際 ops 結構」中間有一個很大的 gap，而**這個 gap 才是真正的商業 insight 在的地方**。

## Dashboard 1 詳細討論 — DEX 市場正在「大者越大」

### (a) DEX 市場已經進入成熟期，正在往大者越大的方向走

在過去 90 天裡，Uniswap（去中心化交易所的第一名）的市占從 ~54% 漲到 ~61%。聽起來只多 7 個百分點，但因為整個以太坊上 DEX 在 90 天內的總成交額大約是 **$158 billion 美元**（每週平均 ~$12 billion），這意味著**每週大約 8-10 億美元的成交額從別人那邊轉到 Uniswap**。

為什麼會這樣？因為 DEX 是個「池子越大 → 大筆交易滑點越小 → 越多人用 → 池子又更大」的正回饋遊戲。Uniswap 已經是最大的池子，所以越來越多人用它，於是它的池子又繼續變大。

**對交易所的意義：**
- 如果你要做一個「幫客戶比價、自動幫客戶去最便宜的 DEX 成交」的功能，預設要對接的就是這前 3 家，不用花力氣把每一家都接上
- 投資 / 商務上評估「跟哪家新 DEX 合作」時，如果那家沒有特別差異化的客群（像 Fluid 專做大戶、Curve 專做穩定幣兌換），通常撐不過幾個月就被市場淘汰

### (b) 每家 DEX 服務的「客人類型」其實差很多

每家 DEX 的「每筆交易平均金額」差異大到誇張：

| DEX | 每筆交易平均金額 (USD) | 推測客人類型 |
|---|---:|---|
| Fluid | $64,000 | 機構 / 大戶 |
| Curve | $16,000 | 機構之間的穩定幣大筆兌換 |
| Balancer | $15,000 | 機構策略 |
| Uniswap | $3,000 | 一般人 |
| Pancakeswap | $1,000 | 小額散戶 |

這意味著：**「DEX」這個詞底下，其實有完全不同的客群在用，不是一塊均質的市場。**

**對交易所的意義：**
- 「自動幫客戶找最佳成交場所」這件事，要按金額決定 — 客戶想換 $50,000 以上的時候，路由到 Fluid 或 Curve（深度好、滑點小）；換 $5,000 以下的時候，路由到 Uniswap 就夠了
- 在挑要上架哪些代幣的時候，要看你想服務哪種客戶。如果你想抓機構流量，就看 Fluid / Curve 上有什麼；想抓散戶熱度，就看 Uniswap 最近有什麼新池
- 跟客戶 / 內部講「中心化交易所 vs 去中心化交易所誰會贏」是錯的框架。實際上是「**不同金額的交易，最適合的場所本來就不一樣**」— 大額機構單可能反而適合 DEX，小額即時單可能適合 CEX

### (c) Balancer 提醒：再大的 DeFi 玩家也會輸

Balancer 在 90 天裡市占從 ~9% 跌到 ~2%（**這個還沒確認原因**，需要查證是真實衰退、還是它的流量跑到別的區塊鏈上了、還是只是 Dune 分類方式變了）。

如果是真實衰退，意義是：**在 DeFi 沒有「大到不會倒」這回事**。Balancer 曾經是穩穩的前 3 名，現在跌到幾乎沒人用。

**對交易所的意義：**
- 「跟誰整合」的決定要動態調整，不要寫死「永遠包含前 3 大」
- 商務團隊分配資源時，看「市占趨勢」比看「目前市占絕對值」更有信號

## Dashboard 2 詳細討論 — USDC 是機構之間的「金流管道」

### (a) USDC 不是給散戶在錢包裡放的東西，是機構之間的「金流管道」

表面上看：以太坊上有 **690 萬個地址**持有 USDC，聽起來像穩定幣已經被大眾廣泛採用了。

但真實的數字是：那 690 萬個地址加起來只佔 11% 的 USDC。**剩下 89% 的 USDC 在前 1 萬個地址手上。** 而這 1 萬個地址裡，大頭是：
- **交易所的冷錢包** — 客戶把 USDC 存在交易所帳戶，這些 USDC 就堆在交易所自己的鏈上錢包（前 10 名裡可以直接看到 Binance 的兩個地址）
- **跨鏈橋的鎖倉錢包** — 你要把 USDC 從以太坊搬到其他區塊鏈時，USDC 會先被鎖在以太坊上的某個錢包，再在目標鏈上發等量的對應幣
- **Circle（發行 USDC 的公司）自己的儲備錢包**
- **大型造市商**（用 USDC 做生意的專業交易機構）

換句話說：**散戶的 USDC 其實是「存在交易所裡」**（所以才會被算進交易所的冷錢包），不是「拿在自己的錢包裡」。

**對交易所的意義：**
- 不要被「穩定幣已經普及」這個故事騙了 — 散戶手上其實沒在自己拿 USDC，他們是把錢存在 CEX 這邊
- 「我們有 X 個用戶持有 USDC」這種行銷數字其實沒太多意義 — 真實的「客戶質量」是那 ~1 萬個機構級錢包
- 推「穩定幣相關產品」（收益、支付、保證金）時，最有價值的目標客戶不是 690 萬個小散戶，是那 1 萬個機構

### (b) 集中度高，意味著「單一玩家風險」也高

$54 billion 美元的 USDC 在以太坊上，**10 個錢包就佔了 27%**。意思是：只要某一個大型參與者出事（交易所暴雷、跨鏈橋被駭、Circle 自己決定大量贖回），一天之內就能搬動數十億美金的供應量。

這不是想像出來的風險 — **2023 年 3 月 Silicon Valley Bank（矽谷銀行）倒閉的時候，USDC 一度從 $1 跌到 ~$0.88**，原因是 Circle 把一部分美元儲備放在 SVB，市場擔心儲備拿不回來。當時就是少數大型機構（避險基金、做市商）大量贖回，造成短時間的供應劇烈變動。

**對交易所的意義：**
- 自家若持有 USDC（很多交易所自己會持有大量穩定幣做為流動性），要監控的不是「USDC 安不安全」這個籠統問題，是**「我曝險的那條鏈上、那 10 個大錢包現在健康嗎」**
- 設計穩定幣相關的金融產品（永續合約保證金、存款生息）時，壓力測試要納入「前 10 個大錢包同時撤出」這種情境，不只是「整體供應收縮 X%」

### (c) 在加密圈，看「持有人數」這類數字幾乎都會誤導

這個結構不只 USDC — USDT、DAI、PYUSD 全都是長這個形狀（PYUSD 更極端，因為 PayPal 自己就是巨大的持有者）。

**對交易所的意義：**
- 凡是看到「X% 的加密用戶持有 Y」這種行銷數字，都要打折看
- 內部做數據報告時，**用「成交額加權」或「持有量加權」的指標，不用「不重複地址數」**。不重複地址數的雜訊太大，幾乎沒辦法拿來做決策

## 對「加密交易所 DS / 市場增長」職位的意義

把上面兩段串起來，可以用一句話概括：

> **鏈上資料表面看起來是散戶在主導，實際上是機構在主導。產品策略要對應到這個實際狀況，不要對應到「去中心化」的對外敘事。**

具體展開到日常工作層面：

1. **算市場規模時** — 用「前 N 家場所的市占」、「前 N 個錢包的持有量」這種指標來估市場大小，不要用「總共有多少不重複地址」
2. **做推薦 / 個人化時** — 「每筆平均交易金額」是強信號的特徵；機構型客戶（Fluid 那類）跟散戶（Uniswap 那類）的需求完全不一樣，要切開來處理
3. **追蹤競爭對手時** — 每週看「前 N 家場所市占的變化」，比追蹤「又有哪家新 DEX 上線」有用得多
4. **管理風險 / 庫存時** — 穩定幣曝險的風險模型要納入「大錢包行為」，不只是看整體供應量的變化

選這兩個分析的目的不是「展示我會寫 SQL」 — 是「**展示我可以從鏈上資料看出產業實際的運作結構，跟對外講的故事中間的差距在哪**」。

## Methodology

- **Tooling**: Dune MCP server connected to Claude Code → 對話式 schema 發現、SQL 撰寫、執行、視覺化、儀表板組裝
- **Schema discovery**: 用 `mcp__dune__searchTables` 找 spell (curated abstraction) 表，不寫原始 logs 解析
- **Source tables**: `dex.trades` (DEX volume) + `stablecoins_evm.balances` (stablecoin holders) + `labels.owner_addresses` (entity labels)
- **Honesty discipline**: 任何具體數字只在 MCP 跑過、結果驗證後才出現
- **Credit spend**: 整個 session 用了 ~12 / 2500 月度 Dune credits（DEX 工作量 ~1.0，穩定幣 ~11.2 — 後者比較貴是因為 stablecoins_evm.balances spell 沒有按天分區，每跑一天都要全表掃）
- **Reproducibility**: 所有 SQL 在 `queries/` 目錄；commit 訊息記錄了每次驗證執行的 cost；dashboard intro 把 caveats 直接寫在使用者第一眼看到的地方

## 附錄：名詞解釋（給沒在鏈上資料生態打滾過的讀者）

### 加密 / 區塊鏈基礎
| 詞 | 意思 |
|---|---|
| 鏈上 (onchain) | 公開記在區塊鏈上、任何人都能查到的資料 |
| 錢包 / 地址 | 區塊鏈上的帳戶，一串 hex 字串 |
| CEX (Centralized Exchange) | 中心化交易所，像 Binance、Coinbase |
| DEX (Decentralized Exchange) | 去中心化交易所，靠鏈上 smart contract 撮合 |
| Self-custody | 你自己保管私鑰的錢包（如 MetaMask）|
| 冷錢包 (cold wallet) | 大額儲存用的離線地址（CEX 把絕大多數客戶資產放這） |

### DEX 相關
| 詞 | 意思 |
|---|---|
| AMM (Automated Market Maker) | DEX 的一種設計：用「流動性池 + 公式」自動報價，沒有掛單簿 |
| 流動性池 (liquidity pool) | 兩種代幣放在一起的池子，使用者跟池交易 |
| LP (Liquidity Provider) | 把資產存進池子提供流動性的人，賺手續費 |
| LP depth / 流動性深度 | 池子可承接多大成交而不大滑點 |
| Aggregator | 一次比多家 DEX 報價、撈最好的成交（如 1inch、0x）|
| Smart order routing | 把訂單拆/送到能拿到最好價格的場所 |
| Swap | DEX 上的「一次交易」術語 — A 換 B |
| Slippage (滑點) | 你預期成交價跟實際成交價的差 |

### 穩定幣相關
| 詞 | 意思 |
|---|---|
| Stablecoin | 設計來釘住美元的代幣（1 USDC ≈ $1）|
| USDC | Circle 公司發行的美元穩定幣，現在第二大 |
| USDT | Tether 公司發行的，目前最大穩定幣 |
| Circle | 發行 USDC 的公司，類似「穩定幣界的央行」|
| Mint / Burn | 發行新 USDC = mint；銷毀 = burn |
| Supply | 市面上流通的代幣數量 |
| Bridge / 跨鏈橋 | 把代幣從一條鏈搬到另一條鏈的協議 |
| Depeg (脫鉤) | 穩定幣價格偏離 $1 |

### 商業 / 數據分析
| 詞 | 意思 |
|---|---|
| pp (percentage points) | 百分點，從 54% 漲到 61% 是 +7 pp，不是 +13% |
| Network effect | 用的人越多 → 服務越好 → 又吸引更多人 |
| Winner-take-most | 不是 100% 贏家通吃，但前 1-2 名拿走絕大多數市占 |
| Segmentation | 把使用者按行為 / 價值分群 |
| Vanity metric | 看起來很大但不代表真實價值的指標 |
| BD | Business Development，商務拓展 |
| Stress test | 壓力測試，模擬極端情境 |
| Treasury | 公司持有的資產儲備 |
